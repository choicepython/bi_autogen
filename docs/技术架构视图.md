## 2. 关键设计决策

### 2.1 Plan&Execute 架构（而非 OrchestratorAgent）

**选择**: PlanAgent + GraphFlow DAG 流水线
**拒绝**: OrchestratorAgent（单Agent+工具集，快速但不稳定）
**理由**: 生产环境优先准确率和稳定性。Plan&Execute 虽然慢（多轮LLM调用），但每个Agent职责单一、可控性强。详见 `docs/archive/a.md`。

### 2.2 exec() 沙箱（而非 subprocess）

**选择**: exec() + AST 阻断 + builtins 裁剪
**拒绝**: subprocess + pickle 序列化
**理由**: exec() 共享进程内存，DataContext 可直接传递 DataFrame，无需序列化开销。通过 31 个 blocked imports + 15 个 removed builtins + AST getattr/type/__dunder__ 阻断保证安全。

### 2.3 GraphFlow DAG 并行（而非 SelectorGroupChat）

**选择**: DiGraphBuilder + GraphFlow
**拒绝**: SelectorGroupChat 动态选择
**理由**: DAG 明确声明任务依赖关系，可并行执行无依赖任务。SelectorGroupChat 需要额外 LLM 调用选择执行者，增加延迟和不确定性。

### 2.4 思考分层 (thinking_enabled)

```python
# 深度思考 (True): 规划/代码/报告
PlanAgent, PyFuncAgent, DataAnalysisAgent, ReportAgent

# 浅层执行 (False): 选API/写SQL/搜索/选图表
APIAgent, SQLAgent, RAGAgent, VisualizationAgent
```

通过 ContextVar `enable_thinking` 传递到 `LoggingChatCompletionClient`，控制 `extra_body.chat_template_kwargs.enable_thinking`。Qwen3 需要显式设置，否则默认启用思考模式。

### 2.5 SSE 流式协议（而非 WebSocket）

**选择**: Server-Sent Events (SSE)
**理由**: 单向流式输出足够，SSE 比 WebSocket 简单，浏览器原生支持 `EventSource`。16种事件类型覆盖完整生命周期。

### 2.6 双级缓存

- **精确缓存**: TTLCache (query hash → ResultCacheEntry)，默认10分钟过期
- **语义缓存**: SentenceTransformer 嵌入向量相似度匹配，阈值0.92
- 默认关闭，按需启用

### 2.7 优雅降级机制

系统支持多层优雅降级，按配置自动选择实现：

| 组件 | 已配置 | 未配置（降级） |
|------|--------|----------------|
| Elasticsearch | ESResourceStore (ES 查询) + `ensure_index_exists()` 自动创建索引 | LocalResourceStore (jieba 分词 + source/*.jsonl) |
| Redis | RedisConversationStore + RedisDataContextCache | InMemory 存储 |
| Langfuse | LangfuseObserver (trace/span/generation) | NoopObserver (no-op) |
| PostgreSQL | asyncpg 连接池 + DBWriter | 指数退避跳过 (1s→2s→4s→...→60s) |
| 搜索工具 | 条件注册 (仅已配置 URL 的工具) | RAGAgent 降级为纯知识回答 |

### 2.8 可观测性平台抽象

`TraceObserver` ABC 定义统一 trace/span/generation 接口，`LangfuseObserver` 实现 Langfuse v3 集成。通过 `observer_factory` 单例工厂按 `langfuse_host` 配置选择实现。集成点：Agent 工具调用、路由决策、LLM 调用。

### 2.9 AgentLayer 职责拆分

`agent_layer.py` 拆分为：
- `dag_executor.py` — DAG 执行 + 事件推送 + 收尾清理
- `plan_executor.py` — PlanAgent 调用 + DAGPlan 解析 + GraphFlow 构建
- `agent_layer.py` — 薄编排层，`run_team` 委托给上述模块

## 5. 技术风险与应对

| 风险 | 应对 |
|------|------|
| LLM API 限流 | 内部队列 + 指数退避重试 |
| Token 超限 | 消息截断 + 历史轮次 ContextSpec 过滤 |
| DAG 执行超时 | `asyncio.timeout(180)` + 失败任务跳过传播 |
| DataContext 内存溢出 | LRU 淘汰 (max 50 keys) + 销毁时数据快照 |
| DB 写入瓶颈 | 异步 Queue + batch INSERT (50条/0.5秒) |
| 代码沙箱逃逸 | 31 blocked imports + AST 阻断 + builtins 裁剪 |
| SSRF 攻击 | DNS 解析 + ipaddress.ip_address() 校验 |
| SQL 注入 | sqlparse 验证 + 参数化查询 |
| ES 不可用 | ResourceStore 降级为本地 jieba 搜索 (source/*.jsonl) |
| ES 索引不存在 | `ensure_index_exists()` 启动时自动根据 `db/es_schema/` schema 创建 |
| Redis 不可用 | 自动降级为 InMemory 存储 |
| Langfuse 不可用 | NoopObserver no-op 降级 |
