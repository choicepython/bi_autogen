
# 多轮对话上下文方案设计

## 1. 架构定位

多轮对话的上下文编排归属 **DispatchLayer**，遵循三层各司其职的原则：

| 层 | 职责 | 对多轮对话的参与 |
|---|---|---|
| **DispatchLayer** | 会话生命周期编排 | 加载历史、指代消解、传递上下文、存储本轮结果 |
| **AgentLayer** | Agent 工厂 + 执行 + 事件翻译 | 消费上下文，构造多轮消息，不负责存取 |
| **RoutingLayer** | 无状态路由决策 | 不感知历史；若需历史信息，由 DispatchLayer 注入 RoutingContext |

独立组件：

| 组件 | 职责 |
|---|---|
| **ConversationStore** | 历史消息的存取与裁剪，接口: `get_history()` / `append_messages()` / `trim()`，可插拔实现（内存/DB/Redis） |

数据流：

```
DispatchLayer.run_stream()
  1. 从 ConversationStore 加载历史消息
  2. 组装 ConversationContext（结构化摘要 + 数据引用）
  3. 指代消解（"用上面的数据" → 具体 DataContext key）
  4. 路由（可携带历史摘要到 RoutingContext）
  5. 把 ConversationContext 传给 AgentLayer
  6. 执行完成后，把本轮 TurnSummary 存回 ConversationStore
```

## 2. 上下文的三个维度

```
┌─────────────────────────────────────────────────┐
│              多轮对话上下文                        │
├─────────────┬──────────────┬────────────────────┤
│  意图层      │  数据层       │  决策层             │
│  用户说了什么 │  有什么数据    │  各Agent做了什么结论  │
│  指代/省略   │  DataFrame目录 │  路由决策+理由       │
│  意图演变    │  数据血缘     │  工具调用+结果摘要    │
└─────────────┴──────────────┴────────────────────┘
```

## 3. 不同 Agent 的上下文需求

### 3.1 公共上下文（所有 Agent）

| 信息 | 内容 | 为什么 |
|------|------|--------|
| 查询历史 | 每轮用户的原始 query | 理解意图演变，解决"再查一下"等省略 |
| 意图摘要 | 每轮路由决策的 task_description | 知道之前做了什么，避免重复 |
| 数据目录 | 当前 session 所有 DataFrame 的 key + schema + 行数 | 跨 Agent 协作的基础——"用上面的数据"指哪个 |

### 3.2 Agent 差异化上下文

**APIAgent**
- 必看：查询历史 + 数据目录 + 之前调用的 API 名称和参数摘要
- 不看：SQL 查询细节、图表配置、报告内容
- 原因：APIAgent 只关心"调哪个接口、传什么参数"，之前的 API 调用结果可避免重复调用

**SQLAgent**
- 必看：查询历史 + 数据目录 + 之前 SQL 查询的表名和返回 schema
- 不看：API 响应体、图表配置、分析算法细节
- 原因：SQLAgent 需要知道表结构，不需要看其他 Agent 的执行过程

**PyFuncAgent**
- 必看：查询历史 + 数据目录（完整 schema，因为要写代码操作 DataFrame）
- 可选：之前 PyFuncAgent 的代码片段和执行结果摘要
- 不看：SQL 原始查询、API 请求细节
- 原因：PyFuncAgent 是通用分析 Agent，数据目录是写代码的依据

**DataAnalysisAgent**
- 必看：查询历史 + 数据目录
- 可选：之前分析结论（"上次预测趋势是上升"）
- 不看：具体算法参数、其他 Agent 的工具调用
- 原因：6 种 ML 工具，关注数据可用性和前序分析结论

**RAGAgent**
- 必看：查询历史（完整，因为需要理解追问语境）
- 可选：之前检索到的知识摘要
- 不看：DataFrame 细节、其他 Agent 执行过程
- 原因：RAGAgent 处理知识问答，追问是最常见场景（"那华为的呢？"）

**VisualizationAgent**
- 必看：查询历史 + 数据目录（必须知道有哪些 DataFrame 可以画图）
- 可选：之前生成的图表类型和 key
- 不看：SQL/API 细节、分析算法
- 原因：画图的前提是"有数据可画"，数据目录是核心

**ReportAgent**
- 必看：查询历史 + 数据目录 + 所有 Agent 的结论摘要
- 可选：之前生成的图表 key（可引用）
- 不看：工具调用参数、中间计算过程
- 原因：ReportAgent 是汇总型 Agent，需要最宽的视野但最浅的深度

**PlanAgent**（最特殊——规划者而非执行者）
- 必看：完整查询历史 + 完整数据目录 + 历史 DAG 结构 + 各 Agent 结论摘要 + 本轮 ES 上下文
- 重要：历史任务执行状态（上轮失败 → 本轮换路）
- 可选：历史工具调用摘要（参数类比）
- 不看：执行过程细节
- 原因：PlanAgent 是唯一需要"全局鸟瞰"的 Agent——它要看到完整的查询演变、数据积累、历史规划，才能做到增量规划而非从零开始

### 3.3 PlanAgent vs 普通 Agent 的本质差异

```
普通 Agent（如 SQLAgent）:
  "我该做什么" → 窄而深
  输入: 当前任务描述 + 数据目录 + 有限的查询历史
  关注: 我的具体任务、可用数据、之前相关的操作

PlanAgent:
  "我该怎么拆" → 宽而浅
  输入: 完整查询历史 + 数据目录 + 历史 DAG + 全部 Agent 结论
  关注: 哪些 Agent 该出场、谁先谁后、数据怎么流转、哪些可复用
```

## 4. 上下文封装结构

### 4.1 Agent 自声明上下文需求（ContextSpec）

**核心设计原则：Agent 自己声明需要什么上下文，ConversationContext 通用消费，新增 Agent 零侵入框架。**

反面模式（switch-case）：

```python
# ✗ 每加一个 Agent 就要改这里，违反开闭原则
def for_agent(self, agent_type):
    if agent_type == "PlanAgent":
        return self._for_plan_agent()
    elif agent_type == "RAGAgent":
        return self._for_rag_agent()
    # ... 无穷分支
```

正确模式（Agent 自声明）：

```python
class ContextSpec(BaseModel):
    """Agent 的上下文需求声明——Agent 自己定义，ConversationContext 消费。"""

    # 查询历史：none / last / full
    query_history: str = "last"

    # 数据目录：none / schema / full
    data_catalog: str = "schema"

    # 结论摘要：none / own / all
    conclusions: str = "own"

    # 历史 DAG：bool
    dag_history: bool = False

    # 工具调用摘要：bool
    tool_summary: bool = False

    # 增量规划提示：bool
    planning_hints: bool = False
```

每个 Agent 在类上声明自己的需求：

```python
class RAGAgent(BIBaseAgent):
    context_spec = ContextSpec(
        query_history="full",      # 追问场景需要完整历史
        data_catalog="none",       # 不关心数据
        conclusions="own",         # 只看自己的结论
    )

class SQLAgent(BIBaseAgent):
    context_spec = ContextSpec(
        query_history="last",
        data_catalog="schema",     # 需要知道表结构
        conclusions="own",
    )

class VisualizationAgent(BIBaseAgent):
    context_spec = ContextSpec(
        query_history="last",
        data_catalog="full",       # 必须知道有什么数据可画
        conclusions="all",         # 可能引用其他 Agent 的结论
    )

class PlanAgent(BIBaseAgent):
    context_spec = ContextSpec(
        query_history="full",
        data_catalog="full",
        conclusions="all",
        dag_history=True,
        tool_summary=True,
        planning_hints=True,
    )

class ReportAgent(BIBaseAgent):
    context_spec = ContextSpec(
        query_history="full",
        data_catalog="schema",
        conclusions="all",         # 汇总型，需要所有结论
    )
```

**新增 Agent 时的变化：**

| 方案 | 新增 Agent 需要改什么 |
|------|----------------------|
| switch-case（反面） | 改 ConversationContext.for_agent() + 改 Agent 本身 |
| 自声明（正面） | **只改 Agent 本身**，加一行 `context_spec = ContextSpec(...)` |

不声明则走默认值（保守策略：last + schema + own），不会泄露不该看的信息。

### 4.2 数据模型

```python
class TaskStatus(str, Enum):
    SUCCESS = "success"           # 正常完成，有结论
    EMPTY = "empty"               # 正常完成，但无数据返回
    PARTIAL = "partial"           # 部分完成（如 API 返回但不完整）
    FAILED = "failed"             # 执行异常
    SKIPPED = "skipped"           # DAG 中被跳过（上游失败）


class AgentConclusion(BaseModel):
    """Agent 执行结论——带状态。"""
    agent_name: str
    status: TaskStatus
    conclusion: str = ""          # 成功时的摘要 / 失败时的原因
    failure_reason: str = ""      # 仅失败时填充: "API超时" / "无权限" / "查询无结果"
    fallback_hint: str = ""       # 建议替代方案: "可尝试SQLAgent从数据库查询"


class DataRef(BaseModel):
    """数据引用——Agent 不拿原始 DataFrame，拿引用。"""
    key: str                      # DataContext 中的 key
    agent: str                    # 哪个 Agent 产出的
    status: TaskStatus            # 数据是否真正可用
    schema: dict[str, str]        # {列名: dtype}
    rows: int                     # 行数
    summary: str                  # 一句话描述（如"2024年1-6月产量数据"）

    @property
    def usable(self) -> bool:
        """数据是否可用于下游消费。"""
        return self.status == TaskStatus.SUCCESS and self.rows > 0


class RoutingSnapshot(BaseModel):
    """路由快照：不暴露路由内部逻辑，只暴露结论。"""
    mode: ExecutionMode
    agent_type: AgentType | None = None
    task_description: str = ""


class TurnSummary(BaseModel):
    """单轮对话的结构化摘要——Agent 看到的是这个，不是原始消息流。"""
    turn_id: int                              # 第几轮
    query: str                                # 用户原始问题
    routing: RoutingSnapshot                  # 路由决策快照
    agent_conclusions: list[AgentConclusion]  # 各Agent的执行结论
    data_produced: list[DataRef]              # 本轮产出的数据引用
    dag_tasks: list[str] | None = None        # 历史 DAG 任务列表（PlanAgent 需要）
    errors: list[str] = []                    # 本轮遇到的错误


class ConversationContext(BaseModel):
    """完整的多轮对话上下文——DispatchLayer 组装，AgentLayer 消费。"""
    session_id: str
    turns: list[TurnSummary]            # 历史轮次摘要
    data_catalog: list[DataRef]         # 当前 session 全部可用数据
    current_query: str                  # 本轮用户问题

    @property
    def available_data(self) -> list[DataRef]:
        """真正可用的数据。"""
        return [d for d in self.data_catalog if d.usable]

    @property
    def failed_data(self) -> list[DataRef]:
        """失败/不可用的数据。"""
        return [d for d in self.data_catalog if not d.usable]

    def for_agent(self, agent_type: AgentType | str) -> str:
        """通用上下文组装：读 Agent 的 context_spec，按需过滤。"""
        spec = self._get_spec(agent_type)
        parts = []

        # 查询历史
        if spec.query_history == "full":
            parts.append(self._render_query_history(full=True))
        elif spec.query_history == "last":
            parts.append(self._render_query_history(full=False))

        # 数据目录
        if spec.data_catalog == "full":
            parts.append(self._render_data_catalog(include_failed=True))
        elif spec.data_catalog == "schema":
            parts.append(self._render_data_catalog(include_failed=False))

        # 结论摘要
        if spec.conclusions == "all":
            parts.append(self._render_conclusions(filter_agent=None))
        elif spec.conclusions == "own":
            parts.append(self._render_conclusions(filter_agent=agent_type))

        # 历史 DAG
        if spec.dag_history:
            parts.append(self._render_dag_history())

        # 增量规划提示
        if spec.planning_hints:
            parts.append(self._render_planning_hints())

        return "\n\n".join(parts)

    def _get_spec(self, agent_type: AgentType | str) -> ContextSpec:
        """从 Agent 类上读取 context_spec，新增 Agent 无需改这里。"""
        from agents.base import BIBaseAgent
        agent_cls = AgentFactory.get_class(agent_type)
        return getattr(agent_cls, "context_spec", ContextSpec())  # 默认保守策略
```

### 4.3 PlanAgent 专属上下文

```python
def _for_plan_agent(self) -> str:
    """PlanAgent 专属上下文：最宽视野 + 历史 DAG + 增量提示。"""

    parts = []

    # 1. 完整查询历史（PlanAgent 需要理解意图演变）
    query_history = "\n".join(
        f"第{t.turn_id}轮: {t.query}" for t in self.turns
    )
    parts.append(f"## 历史查询\n{query_history}")

    # 2. 可用数据（PlanAgent 需要知道有什么数据可复用）
    avail = [f"- {d.key}: {d.summary} ({d.rows}行, 列: {list(d.schema.keys())})"
             for d in self.available_data]
    parts.append("## 可用数据\n" + ("\n".join(avail) or "（无）"))

    # 3. 不可用数据 + 原因 + 替代建议（关键：避免依赖失败数据）
    failed = [
        f"- {d.key}: ❌ {d.status.value} — {d.summary}"
        for d in self.failed_data
    ]
    if failed:
        parts.append("## 不可用数据（请勿依赖）\n" + "\n".join(failed))

    # 4. 历史 DAG 结构（PlanAgent 需要知道之前的规划，避免重复）
    dag_history = "\n".join(
        f"第{t.turn_id}轮: {t.routing.mode.value} → "
        + " → ".join(c.agent_name for c in t.agent_conclusions)
        for t in self.turns
    )
    parts.append(f"## 历史规划\n{dag_history}")

    # 5. 各 Agent 结论摘要（PlanAgent 需要知道哪些结论已存在）
    conclusions = []
    for t in self.turns:
        for c in t.agent_conclusions:
            status_icon = "✓" if c.status == TaskStatus.SUCCESS else "✗"
            conclusions.append(f"- {status_icon} {c.agent_name}: {c.conclusion}")
    parts.append("## 已有结论\n" + "\n".join(conclusions))

    # 6. 增量规划提示
    parts.append(
        "## 规划原则\n"
        "- 已有数据不需要重新获取，直接引用 DataContext key\n"
        "- 已有结论不需要重新计算，直接引用\n"
        "- 仅依赖「可用数据」规划下游任务\n"
        "- 如果上游数据不可用，必须先规划数据获取任务\n"
        "- 优先尝试替代方案（如 APIAgent 失败可换 SQLAgent）\n"
        "- 不可假设数据存在，必须从可用数据目录确认\n"
        "- 只规划本轮新增的任务\n"
        "- 新任务的依赖要明确标注数据来源 key"
    )

    return "\n\n".join(parts)
```

## 5. 上下文封装的五大原则

### 原则一：摘要替代原文

Agent 不看原始 StreamEvent 序列，看 `TurnSummary`。一轮 10 个 LLM_CHUNK 事件，摘要成一句话"APIAgent 查询了本月产量，结果为 1000 件"。token 压缩比约 10:1。

### 原则二：引用替代数据

Agent 不拿完整 DataFrame，拿 `DataRef`。需要数据时通过 DataContext 的 key 按需获取。避免把几万行数据塞进上下文。

### 原则三：结论替代过程

Agent 不看 TOOL_CALL/TOOL_RESULT 的细节，看 `AgentConclusion`。"SQLAgent 执行了 `SELECT * FROM production` 返回 500 行" → "SQLAgent 查询了产量数据，共 500 行"。

### 原则四：按需裁剪（Agent 自声明）

`for_agent(agent_type)` 不是 switch-case，而是通用过滤引擎，读 Agent 类上的 `context_spec` 按需组装：
- RAGAgent: `query_history="full"`（追问场景）
- VisualizationAgent: `data_catalog="full"`（必须知道有什么数据可画）
- ReportAgent: `conclusions="all"`（汇总型，需要所有结论）
- APIAgent: `conclusions="own"`（避免重复调用）
- PlanAgent: 全量声明 + `dag_history=True` + `planning_hints=True`

新增 Agent 只需在类上声明 `context_spec`，零侵入 ConversationContext。

### 原则五：指代消解在注入前完成

"用上面的数据画图" → 在 DispatchLayer 层结合 TurnSummary 解析为"用 DataContext key=`APIAgent_task_1` 的数据画图"，Agent 收到的已经是消解后的指令。

### 原则六：Agent 自声明，框架零侵入

上下文需求由 Agent 自己通过 `ContextSpec` 声明，ConversationContext 只提供通用过滤引擎。新增 Agent 时：
- 只需在 Agent 类上加一行 `context_spec = ContextSpec(...)`
- 不需要修改 ConversationContext、DispatchLayer 或任何框架代码
- 不声明则走默认保守策略（last + schema + own），不会泄露不该看的信息

这是开闭原则的直接体现：对扩展开放（新 Agent 自声明），对修改关闭（框架代码不变）。

"用上面的数据画图" → 在 DispatchLayer 层结合 TurnSummary 解析为"用 DataContext key=`APIAgent_task_1` 的数据画图"，Agent 收到的已经是消解后的指令。

## 6. 失败防护：四层防线

### 第一层：数据模型加状态

`TaskStatus` 枚举 + `AgentConclusion.status` + `DataRef.status` + `DataRef.usable` 属性。上下文不仅有"有没有"，更有"好不好"。

### 第二层：上下文组装时分离可用/不可用

`available_data` 和 `failed_data` 分离。PlanAgent 的上下文明确标注不可用数据及原因，并附替代建议。防止 PlanAgent 基于失败数据做错误规划。

### 第三层：DAG 执行时运行时校验

即使 PlanAgent 规划错了，运行时也要拦住。AgentLayer 在执行每个 Agent 前校验其依赖的 DataContext key 是否存在且非空：

```python
async def _validate_agent_inputs(self, task_node: TaskNode, data_context: DataContext) -> bool:
    for dep_key in task_node.data_dependencies:
        df = data_context.get(dep_key)
        if df is None or len(df) == 0:
            logger.warning("[AgentLayer] 任务 %s 依赖的数据 %s 不可用，跳过", task_node.id, dep_key)
            return False
    return True
```

### 第四层：失败时自动补规划

Agent 失败后，检查下游依赖是否被阻塞，若被阻塞则调用 PlanAgent 做小范围增量重规划：

```python
async def _on_agent_failed(self, failed_task: TaskNode, dag: DAGPlan, session_ctx: SessionContext) -> DAGPlan | None:
    blocked = [t for t in dag.tasks if failed_task.id in t.dependencies]
    if not blocked:
        return None
    # 用 PlanAgent 做增量补规划
    repair_prompt = (
        f"任务 {failed_task.id}({failed_task.agent}) 执行失败，原因: {failed_task.error}。\n"
        f"以下下游任务被阻塞: {[t.id for t in blocked]}。\n"
        f"请重新规划这些任务的替代方案。可用数据: {session_ctx.data_catalog_summary}。"
    )
```

### 四层防线完整示例

```
Turn 1: "查询本月产量"
  APIAgent 执行 → ❌ API超时
  → AgentConclusion(APIAgent, status=FAILED, failure_reason="API超时", fallback_hint="可尝试SQLAgent")
  → DataRef(key=api_1, status=FAILED, rows=0)
  → ConversationContext.data_catalog: [DataRef(status=FAILED)]

Turn 2: "预测下个月的趋势"

  第1层: 数据模型
    available_data = []  (空)
    failed_data = [DataRef(api_1, FAILED)]

  第2层: 上下文组装
    PlanAgent 看到:
      可用数据: （无）
      不可用数据: api_1 ❌ FAILED — API超时，替代: SQLAgent
      规划原则: 必须先获取数据

    PlanAgent 规划:
      [SQLAgent(查产量) → ForecastAgent(预测)]  ← 自动换路

  第3层: 运行时校验（如果 PlanAgent 仍然规划了 ForecastAgent 依赖 api_1）
    _validate_agent_inputs() → api_1 为空 → 跳过 ForecastAgent

  第4层: 失败补规划（如果 ForecastAgent 被跳过）
    通知 PlanAgent: ForecastAgent 因缺少数据被跳过
    PlanAgent 补规划: SQLAgent → ForecastAgent
```

## 7. 典型多轮对话场景

### 场景一：追问

```
Turn 1: "查询本月产量"
  → APIAgent → DataContext[key=api_1]
  → TurnSummary: {query, routing, conclusions: [APIAgent: "本月产量1000"], data: [DataRef(api_1)]}

Turn 2: "画个柱状图"
  → DispatchLayer 指代消解: "画个柱状图" → "用 api_1 的数据画柱状图"
  → VisualizationAgent 收到: current_query + data_catalog + 上一轮结论
  → 执行 → 生成图表
```

### 场景二：增量规划

```
Turn 1: "查询本月产量"
  → PlanAgent 规划: [APIAgent]
  → DataContext[key=api_1] = DataFrame(产量)

Turn 2: "预测下个月的趋势"
  → PlanAgent 看到: api_1 已有产量数据 + 上轮 DAG 是 [APIAgent]
  → 增量规划: [ForecastAgent(data=api_1)]
  → 不再规划 APIAgent，因为数据已经有了

Turn 3: "再对比一下去年同期的"
  → PlanAgent 看到: api_1(本月) + forecast_1(预测) + 上轮 DAG
  → 增量规划: [APIAgent(去年同期) → DataAnalysisAgent(对比分析)]
  → 只新增需要的数据获取任务，复用已有结论
```

### 场景三：失败换路

```
Turn 1: "查询本月产量"
  → APIAgent → ❌ API超时
  → AgentConclusion(APIAgent, FAILED, fallback_hint="可尝试SQLAgent")

Turn 2: "预测下个月的趋势"
  → PlanAgent 看到: 可用数据(无) + 不可用数据(api_1, FAILED, 替代: SQLAgent)
  → 增量规划: [SQLAgent(查产量) → ForecastAgent(预测)]
  → 自动换路，不依赖失败的 APIAgent
```
