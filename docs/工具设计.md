## 1. 工具体系总览

### 1.1 工具的定义

在 `bi_autogen` 中，**工具 = 异步函数 + DataContext 闭包 + FunctionTool 包装**。AutoGen 的 `FunctionTool` 负责 LLM 侧的 schema 暴露与调用分派；业务逻辑由工具函数承担；跨 Agent 的数据共享通过 `DataContext` 完成。

```python
from autogen_core.tools import FunctionTool
from core.data_context import DataContext

def make_python_exec_tool(data_context: DataContext) -> FunctionTool:
    async def _python_exec(code: str) -> str:
        # 工具内部通过闭包捕获的 data_context 读写共享数据
        ...
        return "代码执行成功，结果已存入DataContext(key=...)"  # 返回摘要字符串
    return FunctionTool(func=_python_exec, name="python_exec", description="...")
```

参考实现：`tools/python_exec.py:324`、`tools/sql_query.py:381`、`tools/data_clean.py:266` 等所有 `make_*_tool` 工厂函数。

### 1.2 工具核心约定（架构原则 P5 — 数据流可追踪）

| 约定 | 实现方式 | 代码参考 |
|---|---|---|
| 工具是 `async def` 函数 | 所有 `make_*_tool` 内部 `_xxx` 都是 async | 全部 tools/ |
| 工具通过闭包捕获 `DataContext` | `make_*_tool(data_context)` 注入 | `tools/python_exec.py:324` |
| 工具执行结果写入 `DataContext` | `data_context.put(key, df, meta={...})` | `tools/sql_query.py:362` |
| 工具返回**摘要字符串**给 LLM，不返回原始 DataFrame | `data_context.summarize(key)` | `tools/python_exec.py:305` |
| 跨 Agent 不直接调用，通过 `DataContext` key 传递 | LLM 看到 `key` 后在下游 Agent 引用 | `tools/data_clean.py:255` |
| key 通过 `generate_key()` 生成，不硬编码 | `data_context.generate_key("PyFuncAgent")` | `tools/api_query.py:159` |

### 1.3 数据流路径

```
User Query → Router → Agent → Tool(闭包持有 DataContext)
                              │
                              ├─ 写入：data_context.put(key, df, meta)
                              └─ 返回：摘要字符串 (含 key) 供 LLM 消费
                                       │
                                       └─ LLM 将 key 告知下游 Agent
                                              │
                                              └─ 下游 Agent 取 df = data_context.get(key)
```

**为什么返回摘要而非原始数据**：LLM 的 context window 有限，DataFrame 直接序列化会爆炸。`DataContext.summarize()` 输出"行数 x 列数 + 列名 + 前 N 行 + 数值列统计"，足够 LLM 决策下游动作，原始数据留在内存供后续工具消费。

### 1.5 全局工具注册中心

`tools/global_tools.py` 定义"全局工具"概念：

```python
def build_global_tools() -> list[Any]:
    """构建全局工具列表。当前返回空列表。ask_user 不在此注册。"""
    return []
```

设计区分两类工具：

- **全局工具**：所有 Agent 都有权使用，由 `build_global_tools()` 集中管理，注入到 `BIBaseAgent.__init__` 的 `global_tools` 参数。
- **Agent 专属工具**：各 Agent 在 `__init__` 内通过 `make_*_tool(data_context)` 自建。

当前全局工具列表为空的原因：`ask_user` 虽然语义上是全局工具，但 AutoGen 的 `AssistantAgent.on_messages_stream` 在内部执行工具、无法在执行前拦截 `yield USER_QUESTION`，因此在 plan&execute 架构中 `ask_user` 不作为 AutoGen FunctionTool 注入 DAG agent，而是由 AgentLayer 的 pre-plan 澄清阶段（`_clarify`）在 PlanAgent 层实现。详见 `tools/global_tools.py` 模块 docstring。

首个全局工具落地时，应在 `build_global_tools()` 返回其列表，并在 `AgentFactory.create()` / 各子类 `__init__` 中透传 `global_tools` 参数。

### 2.2 python_exec — Python 代码执行

**文件**：`tools/python_exec.py`
**所属 Agent**：PyFuncAgent（默认数据分析 Agent）
**工厂函数**：`make_python_exec_tool(data_context: DataContext) -> FunctionTool`（`tools/python_exec.py:324`）

#### 签名

```python
async def python_exec(
    code: str,
    dfs: list[Any] | None = None,
    data_context: DataContext | None = None,
) -> str
```

#### 用途

执行 LLM 生成的 Python 代码。LLM 必须在代码中定义 `func_call(dfs)` 函数；`dfs` 是 DataContext 中所有 DataFrame 组成的列表，由工具自动注入。

#### DataContext 集成

- **读**：`make_python_exec_tool` 内部循环 `data_context.list_keys()`，将所有 DataFrame 装入 `dfs` 列表（`tools/python_exec.py:329-333`）。
- **写**：若 `result["data"]` 是 list 则转 `pd.DataFrame`；若 `result` 本身是 DataFrame，直接保存。meta 保存 `tool_name="python_exec"` 和 `code[:2000]`（前 2000 字符）。
- **key**：`data_context.generate_key("PyFuncAgent")`。

#### 安全机制（详见 [§3.1](#31-exec-沙箱)）

- AST 层拦截危险 import、危险内建调用、dunder 属性访问、`dfs` 覆写
- 字符串层黑名单拦截 `.to_csv`/`.read_csv` 等文件 IO 模式
- 移除 15 个危险内建函数
- numpy 类型递归清洗（防 `np.float64` 序列化问题）
- ThreadPoolExecutor + `asyncio.wait_for` 实现 30s 超时

### 2.3 sql_query — SQL 查询

**文件**：`tools/sql_query.py`
**所属 Agent**：SQLAgent
**工厂函数**：`make_sql_query_tool(data_context) -> FunctionTool`（`tools/sql_query.py:381`）

#### 签名

```python
async def sql_query(sql: str, data_context: DataContext | None = None) -> str
```

#### 用途

两阶段安全 SQL 查询管线：

1. **校验阶段**（`_validate_sql`）：清注释 → 检查语句类型（仅 SELECT + CTE 递归）→ 拦截恒真条件 → 参数化
2. **执行阶段**（`_execute_sql`）：asyncpg 连接池 → 自动追加 LIMIT → 超时控制 → 写入 DataContext

#### DataContext 集成

- **读**：无（SQL 是数据源）
- **写**：`pd.DataFrame(rows)` → `data_context.put(key, df, meta={sql, rows, cols})`
- **key**：`generate_key("SQLAgent")`
- **返回**：`"SQL查询完成，返回{N}行数据。{summary}"`

#### 安全机制（详见 [§3.3](#33-sql-注入防御)）

- sqlparse 解析 + 仅允许 SELECT/CTE
- 恒真条件正则拦截（`1=1`、`'a'='a'`、`col=col`、`TRUE`）
- 字面值参数化（`$1, $2, ...`）
- 自动追加 `LIMIT`（默认 1000，可配置）
- 查询超时（默认 30s）
- 错误信息脱敏（不暴露完整参数化 SQL）

#### 关键实现细节

- **连接池**：模块级单例 `_pool`，懒初始化（`tools/sql_query.py:249`），由 `close_sql_pool()` 在程序退出时清理。
- **asyncpg 导入**：在 `_get_pool()` 内部 `import asyncpg`，避免在未安装 asyncpg 的环境直接报错。
- **CTE 递归校验**：`_check_cte_inner` 递归遍历 `Parenthesis` token，确保所有 CTE 内部语句都是 SELECT。详见 `tools/sql_query.py:107-158`。

### 2.4 DynamicAPITool — 动态 API 工具

**文件**：`tools/api_query.py`
**所属 Agent**：APIAgent

#### 类设计

```python
class DynamicAPITool(BaseTool):
    def __init__(
        self,
        api_meta: dict[str, Any],            # ES 返回的 API 元数据
        data_context: DataContext | None = None,
        *,
        custom_env: dict[str, Any] | None = None,
        user_id: str = "",
    ) -> None
```

每个 API 元数据生成一个独立的 `DynamicAPITool` 实例（继承 `autogen_core.tools.BaseTool`），LLM 看到的是带完整参数 schema 的独立工具，而非泛化的 `_call_api_query`。

#### 用途

1. 根据 API 名从 ES 查询 API 元数据（`get_api_from_name`，`tools/api_query.py:53`）
2. `_build_args_model` 根据 `parameters` dict 动态构建 Pydantic BaseModel（`tools/api_query.py:84`）
3. `run()` 委托 `CallApiTool.execute()` 完成 HTTP 调用、响应解析、格式转换
4. 结果 DataFrame 写入 DataContext

#### ES schema → Pydantic 类型映射（`_TYPE_MAP`，`tools/api_query.py:71`）

| ES type | Python type |
|---|---|
| string / 默认 | `str` |
| integer / int | `int` |
| number / float | `float` |
| boolean | `bool` |
| list / List | `list[str]` |
| object | `dict` |

字段必填/默认值规则（`tools/api_query.py:103-110`）：
- `required=True` 且无 default → 必填字段（无默认值）
- 有 default → 使用 ES 提供的默认值
- 否则 → 可选字段，默认 None

#### DataContext 集成

- **写**：`pd.DataFrame(records)` → `data_context.put(key, df, meta={api_name, params})`
- **key**：`data_context.generate_key("APIAgent")`
- **返回**：`f"API '{api_name}' 调用成功，返回 {len(df)} 行数据。\n数据已存入DataContext(key={key})。\n\n{summary}"`

#### 调用链

```
DynamicAPITool.run(args)                      # tools/api_query.py:142
    └─> CallApiTool(api_meta).execute({...})  # tools/api_query.py:380
            ├─> parse_tools(...)              # 参数解析、env 注入、header 构建
            │     └─> extract_customer_env()  # 解析 over_write / no_over_write
            │     └─> build_headers(...)      # utils/common_auth.py IAM 认证
            ├─> call_api(name, method, url)   # _validate_url SSRF 校验 + httpx
            │     └─> httpx.AsyncClient.get/post
            ├─> extract_api_res(rsp, outputs) # 递归提取 outputs 字段
            └─> convert_format(answer, outputs) # 时间格式 + 枚举映射
```

#### 安全机制（详见 [§3.2](#32-ssrf-防御)）

- `_validate_url()`：协议白名单 + 危险主机名拦截 + 域名白名单
- 域名白名单通过 `settings.api_allowed_domains` 配置
- httpx 超时 30s，连接错误/超时分别包装为 `APIQueryError`

#### 错误处理

- `_validate_url` 失败 → `APIQueryError("", detail=...)`
- HTTP 状态码非 200/201 → `APIQueryError(api_name, status_code, detail=response.text[:500])`
- 网络错误 → `APIQueryError(api_name, status_code=400, detail="API 网络不可达请检查防火墙")`
- 超时 → `APIQueryError(api_name, status_code=400, detail="API 响应时间超过10秒，终止请求。")`

> **注意**：`DynamicAPITool.run()` 自身用 `try/except Exception` 包裹，将异常转为字符串返回给 LLM（不抛出），让 LLM 有机会自我修正。

### 2.5 ask_user — 澄清提问

**文件**：`tools/ask_user.py`
**所属 Agent**：PlanAgent（在 `on_messages_stream` 中拦截，不真正执行 func）

#### 签名

```python
def make_ask_user_tool_with_queue(answer_queue: asyncio.Queue[str]) -> FunctionTool

# 内部函数签名
async def _ask_user_impl(
    question: str,
    question_type: str = "open",       # open/choice/multi_choice/confirm
    options: list[str] | None = None,
    context: str = "",
    default: str | None = None,
) -> str  # 从 answer_queue.get() 返回用户答复
```

#### 用途

PlanAgent 在 API 必填参数缺失或需求不明确时调用。**关键设计**：FunctionTool 的 func 不真正执行业务逻辑，只是 `await answer_queue.get()` 阻塞等待用户答复。真正的 yield USER_QUESTION 事件由 PlanAgent 拦截 ToolCallRequestEvent 后处理。

#### AskUserHandler 状态机（`tools/ask_user.py:36-202`）

```
create_question() ──> _questions[id]=UserQuestion, _futures[id]=None, _answers[id]=""
       │
       ▼
yield USER_QUESTION 事件 ──> Gateway 通过 AskUserRegistry 找到 handler
       │
       ▼
wait_for_answer(id) ──> 创建 Future（延迟到此时，确保在 async 上下文）
       │                   │
       │                   ├─ submit_answer 在 wait 之前调用？直接读 _answers
       │                   └─ await asyncio.wait_for(future, timeout)
       ▼                                          ▲
submit_answer(id, answer) ──> _answers[id]=answer ─┘  或 future.set_result(answer)
       │
       ▼
_cleanup(id) ──> 清理 _questions/_futures/_answers
```

#### 关键常量

- `DEFAULT_TIMEOUT_SECONDS = 300`（5 分钟）
- `DEFAULT_MAX_ASKS = 3`（单会话最多 3 次提问）

#### 重要实现细节

1. **Future 延迟创建**：`create_question` 时 `_futures[id]=None`，到 `wait_for_answer` 才创建 `loop.create_future()`。原因：避免在无 event loop 上下文创建 Future 报错。
2. **submit_answer 竞态处理**：若 `submit_answer` 在 `wait_for_answer` 之前调用，答复暂存到 `_answers`，`wait_for_answer` 进入时直接读取并 `_cleanup`。
3. **重复提交拒绝**：`_answers[id]` 已有值时拒绝重复 `submit_answer`。
4. **超时默认值**：超时返回 `uq.default` 或 `"用户未在规定时间内回复，已跳过该问题"`。
5. **会话结束清理**：`cancel_pending()` 把所有未完成 Future 设为 `"会话已结束，问题被取消"`。

### 2.6 dag — DAG 任务提交

**文件**：`tools/dag_tool.py`
**所属 Agent**：PlanAgent

#### 签名

```python
def make_dag_tool(on_plan_created: Callable[[DAGPlan], None]) -> FunctionTool

# 内部函数签名
async def _dag_impl(tasks: list[TaskNode], reasoning: str = "") -> str
```

#### 用途

LLM 规划完成后通过 function calling 提交结构化任务列表。工具内部：

1. 构造 `DAGPlan(reasoning=..., tasks=tasks, is_complete=not tasks)`
2. 调用 `plan.validate_dag()` 校验无环、无缺失依赖
3. 通过回调 `on_plan_created(plan)` 通知 PlanAgent 存储 plan
4. 返回 `"DAG生成成功，共{N}个任务"` 或 `"DAG生成失败：{error}"`

#### 使用样例（PlanAgent 内）

```python
dag_tool = make_dag_tool(lambda plan: setattr(self, "_dag_plan", plan))
# LLM 调用 dag(tasks=[...], reasoning="...") 后，self._dag_plan 即为 DAGPlan
```

参考：`agents/plan_agent.py:77`。

#### 错误处理策略

- `ValueError`（来自 `validate_dag`，如检测到环）→ 返回 `"DAG生成失败：{e}"`
- 其他 `Exception` → 返回 `"DAG生成失败: {e}"`

工具**永不抛出**，所有错误转字符串给 LLM，让 LLM 重新规划。

### 2.8 data_clean — 声明式数据清洗

**文件**：`tools/data_clean.py`

```python
async def render_ppt(report: ReportContent, output_dir: Path, data_context: DataContext | None) -> str:
```

#### 深色主题自动颜色修正（`_is_dark_theme` + `_build_native_pptx`，`tools/ppt_renderer.py:271`）

```python
def _is_dark_theme(theme: dict[str, str]) -> bool:
    bg = theme.get("body_background", "#ffffff")
    # 解析 hex，计算亮度 ITU-R BT.601
    r, g, b = int(bg[0:2], 16), int(bg[2:4], 16), int(bg[4:6], 16)
    luminance = 0.299 * r + 0.587 * g + 0.114 * b
    return luminance < 128
```

原因：原生 PPT 默认白色背景，若 CSS 是深色主题，文字会被设成浅色 → 在 PPT 中不可读。`is_dark=True` 时反转所有文字颜色为深色（`text_color=#1A1A2E`），保留 accent 强调色作为标题。

#### CSS 变量解析（`_parse_theme`，`tools/ppt_renderer.py:237`）

从 CSS 提取 `--var: value;` 形式变量到 dict，并额外解析：
- `body_background` — body 的 background 颜色
- `cover_gradient_start` — 封面渐变起始 rgba（用正则从 `linear-gradient` 提取）

#### 视觉锚点

每页都有：左侧 0.4cm 装饰色条（accent 颜色）、标题下满宽 0.08cm 渐变线、页脚右对齐报告标题（10pt 灰色）。结论页额外有：背景框（conclusion_bg）+ 框内左侧 0.12cm 竖线装饰（accent 颜色）。

#### PDF 导出（`_export_pdf`，`tools/ppt_renderer.py:174`）

合并所有页面 HTML body 内容到一个长 HTML，CSS `@page { size: 1280px 720px; margin: 0; }` + `page-break-after: always`，Playwright `page.pdf()` 直接导出。

`ast.walk(tree)` 遍历所有节点，逐类型检查：

1. **`ast.Import` / `ast.ImportFrom`**：取根模块名（`name.split(".")[0]`），命中 `_BLOCKED_IMPORTS` 即记录违规。
2. **`ast.Call`**：

3. **`ast.Attribute`**（dunder 访问拦截）：若 `node.attr` 以 `__` 开头并以 `__` 结尾，且不在白名单 `_SAFE_DUNDERS={"__init__", "__name__", "__str__", "__repr__", "__len__", "__iter__", "__next__"}` → 违规。目的：拦截 `obj.__class__`、`obj.__bases__`、`obj.__subclasses__()` 等逃逸路径。
4. **`ast.Assign`**：若 `target.id == "dfs"` → 违规，防止覆写注入的 `dfs` 变量。

#### 3.1.5 关键设计点：为什么 `__import__` 保留在 builtins

```python
# 注意: __import__ 不能从 builtins 移除（import 语句依赖），但 AST 层拦截直接调用 __import__("os")
_REMOVED_BUILTINS = { ... 不含 __import__ ... }
_BLOCKED_CALLS = _REMOVED_BUILTINS | {"__import__"}
```

**原因**：Python 的 `import os` 语句在底层调用 `__import__("os")`。如果从 `__builtins__` 移除 `__import__`，所有 `import` 都会失败（包括允许的 `import pandas as pd`）。因此：

- **`_REMOVED_BUILTINS` 不含 `__import__`** — 内建环境保留 `__import__`，使 `import` 语句能正常工作
- **`_BLOCKED_CALLS` 含 `__import__`** — AST 层拦截直接调用 `__import__("os")` 形式
- **`_BLOCKED_IMPORTS` 拦截模块名** — `import os`、`from os.path import ...` 由 AST 检查拦掉

三层防御协同：import 语句走 AST 模块黑名单；动态 `__import__("os")` 走 AST Call 黑名单；其他内建危险函数走 `__builtins__` 移除。

### 3.2 SSRF 防御

**文件**：`tools/api_query.py:24-50`（`_validate_url`）

#### 设计目标

防止 LLM 生成的 URL 触发 SSRF（如访问 `http://169.254.169.254/` 元数据接口、`http://127.0.0.1:8080/admin` 内网服务）。

#### 检查项

```python
def _validate_url(url: str) -> None:
    parsed = urlparse(url)
    # 1. 协议白名单：仅允许 http/https
    if parsed.scheme not in ("http", "https"):
        raise APIQueryError("", detail=f"不允许的协议: {parsed.scheme}")

    hostname = parsed.hostname or ""
    # 2. 危险主机名拦截：0.0.0.0、::1、[::1]
    _BLOCKED_HOSTNAMES = {"0.0.0.0", "::1", "[::1]"}
    if hostname.lower() in _BLOCKED_HOSTNAMES or hostname in _BLOCKED_HOSTNAMES:
        raise APIQueryError("", detail=f"不允许访问内网地址: {hostname}")

    # 3. 域名白名单（仅当 settings.api_allowed_domains 配置时启用）
    if settings.api_allowed_domains:
        if hostname not in settings.api_allowed_domains:
            raise APIQueryError("", detail=f"域名不在白名单内: {hostname}")
```

#### 为什么字符串前缀匹配不够（架构原则 P9）

**字符串前缀匹配的常见错误**：

```python
# 错误示范（被弃用）
if hostname.startswith(("127.", "10.", "192.168.", "169.254.")):
    raise SSRFError(...)
```

这种检查可被多种方式绕过：

| 绕过方式 | 示例 | 字符串匹配能否识别 |
|---|---|---|
| IPv6 地址 | `http://[::1]/`、`http://[::ffff:127.0.0.1]/` | 否 |
| 十六进制 IP | `http://0x7f000001/` (127.0.0.1) | 否 |
| 八进制 IP | `http://0177.0.0.1/` | 否 |
| 十进制 IP | `http://2130706433/` (127.0.0.1) | 否 |
| DNS rebinding | 第一次解析为公网 IP 通过校验，第二次解析为内网 IP 实际访问 | 否 |

#### 正确做法（生产环境应升级为）

```python
import socket
import ipaddress

def _validate_url_strict(url: str) -> None:
    parsed = urlparse(url)
    hostname = parsed.hostname
    # 1. DNS 解析
    try:
        addrs = socket.getaddrinfo(hostname, None)
    except socket.gaierror:
        raise APIQueryError("", detail=f"DNS 解析失败: {hostname}")
    # 2. 校验每个解析结果是否为内网 IP
    for family, _, _, _, sockaddr in addrs:
        ip = ipaddress.ip_address(sockaddr[0])
        if ip.is_private or ip.is_loopback or ip.is_reserved or ip.is_link_local:
            raise APIQueryError("", detail=f"内网地址被禁止: {ip}")
```

> **当前实现状态**：`tools/api_query.py` 的 `_validate_url` 完成了协议白名单 + 危险主机名黑名单 + 域名白名单三层防御。完整 DNS 解析 + `ipaddress.ip_address()` 校验应作为防御深化方向，覆盖 IPv6/十六进制/八进制/DNS rebinding 等高级绕过。AGENTS.md P9 原则要求"DNS 解析 + ipaddress.ip_address() 校验"作为必须项，建议在后续迭代中补齐。

#### 3.3.2 sqlparse Token.Keyword.CTE 陷阱（关键经验）

**错误代码**（陷阱）：

`ttype in Keyword` 用的是 sqlparse 的 ttype 继承链检查（`__contains__` 实现遍历父类型），能识别 `Token.Keyword.CTE` 属于 `Keyword` 家族。

### 4.4 LRU 淘汰（`put` 内，第 27-33 行）

```python
async def put(self, key: str, df: pd.DataFrame, meta: dict[str, object] | None = None) -> None:
    if not isinstance(df, pd.DataFrame):
        raise DataContextError(key, "put", "value must be a pandas DataFrame")
    async with self._lock:
        # 超出上限时淘汰最旧条目
        if key not in self._store and len(self._store) >= self._MAX_KEYS:
            oldest = next(iter(self._store))  # dict 保持插入顺序（Python 3.7+）
            del self._store[oldest]
            del self._metadata[oldest]
            logger.warning("[DataContext] 超出 %d key 上限，淘汰: %s", self._MAX_KEYS, oldest)
        self._store[key] = df
        self._metadata[key] = meta or {}
```

**淘汰策略**：FIFO（first-in-first-out），利用 Python dict 自 3.7 起保持插入顺序的特性。`next(iter(self._store))` 取最早插入的 key。

**为什么不是真正的 LRU**：读操作 `get(key)` 不更新顺序（dict 重新赋值才会移到末尾）。若需要严格 LRU，应在 `get` 中 `self._store[key] = self._store.pop(key)` 重新插入。当前实现为简化 FIFO，对 BI 分析场景足够（数据流通常是单向的：先采集后分析再可视化）。

### 4.5 摘要生成（`summarize`，第 59 行）

```python
def summarize(self, key: str, max_rows: int | None = None, max_cols: int | None = None) -> str:
    df = self._store.get(key)
    if df is None:
        return f"数据集 '{key}' 不存在。可用数据集: {self.list_keys()}"

    max_rows = max_rows or settings.data_context_max_summary_rows
    max_cols = max_cols or settings.data_context_max_summary_cols

    # 5 部分拼接
    parts = [
        f"数据集 '{key}': {len(df)} 行 x {len(df.columns)} 列",
        f"列名: {list(df.columns)}",
        f"数据类型: {dict(df.dtypes)}",
        f"前 {max_rows} 行:\n{df_display.to_string()}",
    ]
    # 数值列 describe()
    if numeric_cols:
        parts.append(f"数值列统计:\n{df[numeric_cols].describe().to_string()}")
    # 数据来源溯源（meta 含 api_name 或 tool_name 时追加）
    source_line = self._render_source(meta)
    if source_line:
        parts.append(source_line)
```

**关键设计**：摘要包含**溯源信息**，让下游 Agent 知道数据来自哪个 API/工具/参数。`_render_source` 根据 meta 中的 `api_name` 或 `tool_name` 字段渲染数据来源行（第 89 行）。

### 4.6 全量摘要（`all_summaries`，第 105 行）

```python
def all_summaries(self) -> str:
    parts: list[str] = []
    if self._store:
        parts.append("\n\n---\n\n".join(self.summarize(k) for k in self._store))
    if self._charts:
        parts.append(self.chart_summaries())  # 列所有 chart 的元信息
```

```python
def _build_args_model(api_meta: dict[str, Any]) -> type:
    parameters = api_meta.get("parameters", {})
    fields: dict[str, Any] = {}
    for param_name, param_schema in parameters.items():
        py_type = _TYPE_MAP.get(param_schema.get("type", "string"), str)
        desc = param_schema.get("description", param_name)
        is_required = param_schema.get("required", False)
        default_value = param_schema.get("default")

        if is_required and default_value is None:
            fields[param_name] = (py_type, Field(description=desc))
        elif default_value is not None:
            fields[param_name] = (py_type, Field(default=default_value, description=desc))
        else:
            fields[param_name] = (py_type, Field(default=None, description=desc))

    return create_model(f"{api_meta['name']}_args", **fields)
```

**输出**：每个 API 生成一个独立的 Pydantic BaseModel 子类，作为 `BaseTool.args_type`。LLM 看到的是带完整参数 schema 的独立工具（"调用 lps_transBox 时需要传 warehouse_id 必填、date 可选"），而不是泛化的"调用任意 API"工具。

### 5.8 用户 env 注入（`extract_customer_env`）

```python
                self.no_over_write[key] = value['value']
            else:
                self.over_write[key] = value['value']
```

### 5.9 HTTP 调用与错误处理（`call_api`）

`tools/api_query.py:236-265`：

```python
async def call_api(self, api_name, method: str, url: str):
    _validate_url(url)  # SSRF 防护
    try:
        async with httpx.AsyncClient(timeout=30.0) as client:
            if method.lower() == "get":
                # GET 参数中 dict 类型转 JSON 字符串，None 转空串
                if self.call_api_param:
                    for k, v in self.call_api_param.items():
                        if isinstance(v, dict):
                            self.call_api_param[k] = json.dumps(v, ensure_ascii=False)
                        elif v is None:
                            self.call_api_param[k] = ''
                response = await client.get(url, headers=self.default_headers, params=self.call_api_param)
            elif method.lower() == "post":
                response = await client.post(url, headers=self.default_headers, json=self.call_api_param)
            else:
                raise APIQueryError(api_name, status_code=404, detail=f"{method} 请求方式ChatBI-Api暂未集成")

            if response.status_code not in [200, 201]:
                raise APIQueryError(api_name, status_code=response.status_code, detail=response.text[:500])
            return response.json()
    except APIQueryError:
        raise
    except httpx.ConnectError:
        raise APIQueryError(api_name, status_code=400, detail="API 网络不可达请检查防火墙") from None
    except httpx.TimeoutException:
        raise APIQueryError(api_name, status_code=400, detail="API 响应时间超过10秒，终止请求。") from None
    except Exception as e:
        raise APIQueryError(api_name, detail=str(e)) from e
```

**重试机制**：当前 `DynamicAPITool` 本身**不重试**（由调用方决定）。错误以字符串形式返回给 LLM，让 LLM 自我修正（如调整参数后重试）。

### 5.10 响应解析（`extract_api_res`）

`tools/api_query.py:267-302`：递归遍历 API 响应 dict/list，按 `outputs` 字段的 `value → name` 映射提取目标字段。

**算法**：

1. 对每个 dict，若 key 在 `re_metric` 映射中 → 更新 `extract_data`
2. 否则若 value 是 dict/list 且非空 → 加入 `subset_data` 待后续递归
3. 递归处理 `subset_data`，传递当前 `extract_data` 作为 memory
4. 无子集且 `extract_data` 非空且本次有 update → 追加到结果列表

**坑位**：避免选择嵌套的根作为输出字段，否则会导致 key 重复解析。

### 6.2 工具注册模式（架构原则 P2 — 开闭原则）

所有 Agent 在 `__init__` 中通过 `make_*_tool(data_context)` 创建工具列表，传给 `BIBaseAgent.__init__(tools=...)`：

```python
class PyFuncAgent(BIBaseAgent):

        python_tool = make_python_exec_tool(data_context)
        super().__init__(model_client=model_client, data_context=data_context, tools=[python_tool], ...)
```

**新增工具的扩展方式**（开闭原则）：

1. 在 `tools/` 下新建 `my_tool.py`，定义 `async def my_tool(...)` 函数和 `make_my_tool_tool(data_context) -> FunctionTool` 工厂
2. 在对应 Agent 的 `__init__` 中 `my_tool = make_my_tool_tool(data_context)` 并加入 `tools=[]`
3. **禁止**修改 `core/` 下的框架代码（AgentLayer、DispatchLayer、AgentFactory）
4. **禁止**在 `agents/__init__.py` 中做集中导出（会导致循环导入）
