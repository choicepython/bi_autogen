
# 系统架构视图

## 1. 架构总览

BI AutoGen 是基于 AutoGen SDK 构建的 BI 数据分析智能体系统。采用**三层架构**，每层职责清晰、不可越界：

## 2. 三层架构详解

### 2.1 BITeam — 薄门面 (`core/team.py`)

系统的唯一公共入口，保持 API 稳定，所有工作委托给 DispatchLayer。

```python
class BITeam:
    async def run(task) -> tuple[str, TraceRecorder]           # 同步结果
    async def run_stream(task) -> AsyncGenerator[StreamEvent]  # 流式事件
    async def run_stream_sse(task) -> AsyncGenerator[str]      # SSE格式
    async def shutdown()                                        # 优雅关闭
```

- `main.py` 和 `gateway/app.py` 只依赖 BITeam，不感知内部实现
- `shutdown()` 清理 ContextVar、停止 DB writer、关闭连接池

### 2.2 DispatchLayer — 调度层 (`core/dispatch.py`)

调度层只管**编排**（路由 → 执行 → 后处理），不管持久化细节。

**核心流程** (`run_stream`):

```
1. SessionManager.start()
   ├── 初始化 ContextVar (session_id, chat_id, enable_thinking)
   ├── 创建 TraceRecorder
   ├── DB写入 session(running)
   ├── 加载多轮对话历史 (ConversationStore)
   ├── ES上下文发现 (fetch_es_context)
   └── 缓存检查 (result_cache.lookup)

2. 缓存命中? → SessionManager.replay_cache() → return

3. 路由: RoutingLayer.route()
   └── BIRouter 3层路由决策

4. 执行: AgentLayer.run_single_agent() 或 run_team()
   └── 产出 TurnResult (显式结果契约)

5. SessionManager.finish(routing, events, start, turn_result)
   ├── DB写入 Agent执行记录 + DAG规划记录
   ├── 存储多轮对话 TurnSummary
   ├── DB更新 session(completed/error)
   ├── 后台异步摘要 (summarize_background)
   ├── 结果缓存存储
   └── yield SESSION_END
```

**关键设计**:
- `create_model_client()` 工厂方法创建 OpenAIChatCompletionClient
- `LoggingChatCompletionClient` 包装器记录 LLM 请求/响应
- ContextVar 在 `finally` 块中清理，确保所有路径（含缓存命中）都清理

### 2.3 RoutingLayer — 路由层 (`core/routing_layer.py` + `core/router.py`)

3层路由决策，从快到慢逐层降级：

| 层 | 方法 | 延迟 | 机制 |
|----|------|------|------|
| Layer 1 | 参数路由 | 0ms | `agent_type` 参数 / 闲聊关键词正则匹配 |
| Layer 2 | 规则路由 | ~5ms | 数据/分析关键词 + ES工具召回 + 数据目录感知 |
| Layer 3 | 意图识别 | ~200ms | LLM 意图分类（复用Layer2的ES结果） |

**优化策略**:
- ES上下文只在 Layer 2 查询一次，Layer 3 复用
- Layer 2 命中时跳过 Layer 3 LLM 调用
- 路由结果 TTL 缓存（5分钟，多轮对话不缓存）
- 数据目录感知：已有可用数据且查询为分析类时，直接走 FULL_TEAM

**路由结果** (`RoutingResult`):
```python
@dataclass
class RoutingResult:
    layer: int                    # 命中层级 1/2/3
    mode: ExecutionMode           # SINGLE_AGENT / FULL_TEAM
    agent_type: AgentType | None  # 目标Agent（SINGLE_AGENT时）
    task_description: str         # 传给Agent的任务描述
    reasoning: str                # 路由理由
```

**中间件支持**: RoutingLayer 支持注册 `RoutingMiddleware`，可在路由前后插入逻辑。

### 2.4 AgentLayer — 执行层 (`core/agent_layer.py`)

负责 Agent 创建、DAG 构建、执行、结果汇总。`agent_layer.py` 已拆分为薄编排层 + 两个专职模块：`run_team` 委托给 `PlanExecutor`（规划）与 `DagExecutor`（执行）。

**两条执行路径**:

```
SINGLE_AGENT 路径:
  AgentFactory.create() → Agent.on_messages_stream() → EventTranslator → yield StreamEvent

FULL_TEAM 路径:
  Phase 1: PlanAgent 规划 → DAGPlan          (PlanExecutor)
  Phase 2: AgentFactory + DiGraphBuilder → GraphFlow  (PlanExecutor)
  Phase 3: GraphFlow.run_stream() → EventTranslator → yield StreamEvent  (DagExecutor)
  Phase 4: 收尾 (摘要提取 + 结果合并 + 缓存保存 + TaskContext销毁)  (DagExecutor)
```

**核心组件**:

| 组件 | 文件 | 职责 |
|------|------|------|
| AgentFactory | `core/agent_factory.py` | 惰性注册表 + importlib 延迟加载 |
| EventTranslator | `core/event_translator.py` | AutoGen事件 → StreamEvent |
| TableFormatter | `core/table_formatter.py` | DataFrame → TABLE事件 (numpy净化+列截断) |
| PlanExecutor | `core/plan_executor.py` | PlanAgent 调用 + DAGPlan 解析 + GraphFlow 构建 |
| DagExecutor | `core/dag_executor.py` | DAG 执行 + 事件推送 + 收尾清理 |
| GraphFlow | AutoGen SDK | DAG并行执行引擎 |

## 4. 核心设计模式

### 4.1 ContextSpec 自声明模式

Agent 通过类属性声明自己的上下文需求，框架无需为每个 Agent 写 if 分支：

```python
class ContextSpec(BaseModel):
    query_history: str = "last"    # none / last / full
    data_catalog: str = "schema"   # none / schema / full
    conclusions: str = "own"       # none / own / all
    dag_history: bool = False
    tool_summary: bool = False
    planning_hints: bool = False

# Agent 自声明
class PlanAgent(BIBaseAgent):
    context_spec = ContextSpec(
        query_history="full", data_catalog="full",
        conclusions="all", dag_history=True, planning_hints=True,
    )
```

`on_before_turn` 钩子根据 ContextSpec 构建历史消息，注入到 LLM messages 中。**符合开闭原则**：新增 Agent 只需声明 ContextSpec，框架代码无需修改。

### 4.2 TurnResult 显式契约

替代此前通过 `StreamEvent.data` 传递 sideband 字典的隐式模式：

```python
@dataclass
class TurnResult:
    events: list[StreamEvent] = field(default_factory=list)
    agent_records: list[AgentExecutionRecord] = field(default_factory=list)
    plan_record: PlanRecord | None = None
    bg_summary: str | None = None
```

- `AgentLayer` 产出 TurnResult（执行记录写入 `agent_records`，规划记录写入 `plan_record`）
- `SessionManager.finish()` 消费 TurnResult（读取记录写入 DB）
- 类型安全，schema 集中，消除 `ev.data["_db_record"]` 等隐式 sideband key

### 4.3 AgentFactory 惰性注册表

```python
class AgentFactory:
    _MODULE_MAP: dict[AgentType, str] = {
        AgentType.API: "agents.api_agent.APIAgent",
        AgentType.PYFUNC: "agents.pyfunc_agent.PyFuncAgent",
        # ...
    }
    _CACHE: dict[AgentType, type] = {}

    @classmethod
    def _resolve(cls, agent_type: AgentType) -> type:
        """importlib 延迟加载 + 缓存，消除循环导入。"""
        if agent_type not in cls._CACHE:
            module_path, class_name = cls._MODULE_MAP[agent_type].rsplit(".", 1)
            module = importlib.import_module(module_path)
            cls._CACHE[agent_type] = getattr(module, class_name)
        return cls._CACHE[agent_type]

    @classmethod
    def register(cls, agent_type: AgentType, module_path: str) -> None:
        """P2开闭扩展点：新增Agent无需修改框架。"""
        cls._MODULE_MAP[agent_type] = module_path
```

### 4.4 DataContext 共享存储

Agent 间通过 DataContext 传递 DataFrame 数据：

```python
class DataContext:
    _data: dict[str, pd.DataFrame]   # key → DataFrame
    _lock: asyncio.Lock              # 并发安全
    _MAX_KEYS: int = 50              # LRU淘汰上限

    async def put(self, key: str, df: pd.DataFrame) -> None
    def get(self, key: str) -> pd.DataFrame | None
    def list_keys(self) -> list[str]
    def all_summaries(self) -> str   # 供后台摘要
```

- Key 通过 `generate_key(agent_name, task_id)` 生成，不硬编码
- `asyncio.Lock` 保护并发写入
- LRU 淘汰策略防止内存溢出
- **跨 Session 隔离**：每个会话独立的 DataContext

### 4.5 结果缓存

```python
# 精确缓存 (TTLCache)
result_cache.lookup(query, source_site) -> CacheLookupResult
result_cache.store(query, source_site, cache_entry)

# 语义缓存 (SemanticCache, 可选)
# 基于 SentenceTransformer 嵌入向量相似度匹配
# 阈值: semantic_cache_threshold (默认0.92)
```

- 缓存命中时重放 StreamEvent（替换 session_id 和 seq）
- 多轮对话不复用首轮缓存
- 默认关闭，通过 `BI_RESULT_CACHE_ENABLED=true` 启用

### 4.6 StreamEvent SSE 协议

16种事件类型的统一 SSE 协议：

```
SESSION_START → PLAN_START → PLAN_COMPLETE → AGENT_START →
  (TOOL_CALL → TOOL_RESULT)* → (LLM_CHUNK | THINK_CHUNK)* →
  (DATA_STORED)* → AGENT_END → ... → SESSION_END
```

特殊事件：
- `TABLE` — 结构化表格数据（列名 + 行数据）
- `USER_QUESTION` / `USER_ANSWER` — PlanAgent 主动向用户提问

### 4.7 优雅降级机制

系统支持多层优雅降级，按配置自动选择实现，确保核心链路在依赖缺失时仍可运行：

| 组件 | 已配置 | 未配置（降级） |
|------|--------|----------------|
| Elasticsearch | ESResourceStore (ES 查询) | LocalResourceStore (jieba 分词 + source/*.jsonl) |
| Redis | RedisConversationStore + RedisDataContextCache | InMemory 存储 |
| Langfuse | LangfuseObserver (trace/span/generation) | NoopObserver (no-op) |
| PostgreSQL | asyncpg 连接池 + DBWriter | 指数退避跳过 (1s→2s→4s→...→60s) |
| 搜索工具 | 条件注册 (仅已配置 URL 的工具) | RAGAgent 降级为纯知识回答 |

**关键工厂模块**:

| 模块 | 职责 |
|------|------|
| `core/resource_store.py` | `ResourceStore` ABC + `LocalResourceStore` / `ESResourceStore` 实现 |
| `core/resource_factory.py` | 按 ES 配置选择资源存储实现 |
| `core/store_factory.py` | 按 Redis 配置选择 `RedisConversationStore` / `RedisDataContextCache` 或 InMemory 实现 |
| `observability/trace_observer.py` | `TraceObserver` ABC，统一 trace/span/generation 接口 |
| `observability/langfuse_observer.py` | Langfuse v3 实现 |
| `observability/observer_factory.py` | 按 `langfuse_host` 配置选择 `LangfuseObserver` / `NoopObserver` |

降级对上层透明：调用方只依赖抽象接口（`ResourceStore` / `TraceObserver` / 存储接口），工厂按配置注入具体实现，业务代码无需感知。

## 5. SessionManager 会话生命周期

```
start()
├── _init_context_vars()          # session_id, chat_id, enable_thinking
├── TraceRecorder()               # 追踪记录器
├── _write_session_running()      # DB: session(running)
├── _load_history()               # ConversationStore 加载多轮历史
├── _fetch_es_context()           # ES API+知识召回 (整个会话只查一次)
└── _check_cache()                # 结果缓存检查

replay_cache()                    # 缓存命中: 重放事件 + DB + SESSION_END

record_routing()                  # DB: routing_decision

finish(routing, events, start, turn_result)
├── _record_agent_executions()    # DB: agent_execution (从TurnResult读取)
├── _record_plan()                # DB: dag_plan (从TurnResult读取)
├── _store_turn_summary()         # ConversationStore 存储TurnSummary
├── _write_session_final()        # DB: session(completed/error)
├── summarize_background()        # 后台异步摘要 (asyncio.create_task)
├── _store_result_cache()         # 结果缓存存储
└── yield SESSION_END

cleanup()                         # ContextVar清理 (finally块)
```

## 6. 多轮对话架构

### 6.1 上下文层级

```
SessionContext (会话级)
├── conversation_context: ConversationContext
│     ├── turns: list[TurnSummary]           # 历史轮次
│     ├── data_catalog: list[DataRef]        # 数据目录
│     └── current_query: str                 # 当前查询
├── api_meta: list[dict]                     # ES召回的API元数据
├── skills: list[dict]                       # ES召回的业务技能
└── _failed_task_ids: set[str]               # 失败任务追踪

TaskContext (任务级, DAG中每个节点一个)
├── session: SessionContext                  # 反向引用
├── data_context: DataContext                # 共享DataFrame
├── task_id: str
└── final_answer: str
```

### 6.2 TurnSummary 结构

每轮对话结束后存储 TurnSummary，包含：
- `query` — 用户查询
- `routing` — 路由快照 (RoutingSnapshot)
- `agent_conclusions` — 各Agent结论列表
- `data_produced` — 产出的数据引用 (DataRef)
- `dag_tasks` — DAG任务ID列表

### 6.3 数据目录 (DataRef)

```python
class DataRef(BaseModel):
    key: str                    # DataContext 中的 key
    summary: str                # 数据摘要
    usable: bool                # 是否可用
    schema: dict[str, str]      # 列名 → 类型
    source: dict                # 数据来源 (api_name/tool_name + params)
```

PlanAgent 和 VisualizationAgent 可看到完整数据目录，实现数据复用和溯源。

## 7. 扩展指南

### 7.1 新增 Agent

1. 在 `agents/` 下创建 `my_agent.py`，继承 `BIBaseAgent`
2. 声明 `context_spec`、`prompt_template`、`thinking_enabled`、`agent_description`
3. 在 `core/agent_factory.py` 的 `_MODULE_MAP` 中注册（或调用 `AgentFactory.register()`）
4. 在 `models/routing.py` 的 `AgentType` 枚举中添加类型
5. 创建对应的 prompt 模板 `config/prompts/agents/my_agent.md.j2`

**禁止**: 修改 `core/agent_layer.py`、`core/dispatch.py` 等框架代码。

### 7.2 新增工具

1. 在 `tools/` 下创建 `my_tool.py`，定义 `async def my_tool(...)` 函数
2. 通过 `FunctionTool` 包装，在 Agent 的 `__init__` 中注册
3. 工具闭包捕获 `DataContext`，执行结果写入 DataContext 并返回摘要字符串

### 7.3 新增路由中间件

```python
class MyMiddleware(RoutingMiddleware):
    async def before_route(self, query: str, context: RoutingContext) -> str:
        # 修改查询或添加上下文
        return query

    async def after_route(self, query: str, result: RoutingResult, context: RoutingContext) -> RoutingResult:
        # 修改路由结果
        return result

# 注册
dispatch.routing_layer.add_middleware(MyMiddleware())
```

## 8. 架构原则

| 原则 | 说明 |
|------|------|
| P1 分层职责不可越界 | core/ 只管编排；agents/ 只管行为；tools/ 只管 I/O；models/ 只管数据结构 |
| P2 开闭原则 | 新增 Agent/工具不改框架代码，通过自声明接入 |
| P3 补丁思维零容忍 | 找根因修源头，不 try/except pass 吞异常 |
| P4 改动范围最小化 | 一次改动聚焦一个关注点，影响 3-5 文件以内 |
| P5 数据流可追踪 | User → Router → Agent → Tool → DataContext → 下游Agent |
| P6 提示词与代码分离 | Prompt 存放在 `config/prompts/` Jinja2 模板中 |
| P7 异步与并发安全 | 所有 I/O 用 async def；ContextVar 在 finally 清理；共享资源用 Lock |
| P8 测试验证架构不变量 | 为架构约束写断言测试；Mock LLM 不命中真实 API |
| P9 安全底线 | SSRF: DNS解析+ipaddress校验；SQL: sqlparse+参数化；代码: exec沙箱 |

详细原则见 `AGENTS.md`。
